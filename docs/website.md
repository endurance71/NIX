# Website — nix.shipapp.pl

Static website for NiX (`web/site/`), served by Caddy on the ShipApp VPS from `/srv/nix-site`.

- `index.html` (PL) and `en/index.html` are generated by `npm run generate:site`. The scenes mirror the
  in-app welcome tour as CSS motion, so edit the copy in `scripts/generate-site.mjs` and the motion in `site.css`.
- `privacy/`, `terms/` and `support/` are generated by `npm run generate:legal-pages` from the same source as
  the app (`src/lib/legalDocuments.ts`).
- `npm run check:site` and `npm run check:legal-pages` fail when a generated page is stale.
- `img/` holds web-sized copies of the AI-generated onboarding photos, exported from
  `assets/onboarding/source/` by `npm run brand:onboarding` (see `assets/onboarding/CREDITS.md`).
- Local preview: the `nix-site` entry in `.claude/launch.json` (`python3 -m http.server 4173 --directory web/site`).

## Deploy

1. One-time: the `nix.shipapp.pl` block in the ShipApp repo's Caddyfile and the `/srv/nix-site` read-only mount
   in its `compose.yaml` (endurance71/shipapp#157). After merging, on the host: `git pull`, then
   `docker compose up -d --force-recreate caddy`. A new volume needs a recreate; a reload is not enough.
2. Every change: `npm run deploy:site` streams `web/site` to `/srv/nix-site` over SSH (`contabo-mtle`).
   - It refreshes the directory in place, because the bind mount follows the directory.
   - Static files need no Caddy restart.

## /invite/<token> and the AASA

The friend invite links NiX shares (`src/lib/friendInvite.ts`, `https://nix.shipapp.pl/invite/<token>`) land on
`/invite/` (generated by `generate-site.mjs`): with NiX installed iOS opens the app directly through the
universal link, everyone else sees the App Store page, and link previews (the share sheet, Messages) read its
Polish title, description and `nix-share-image.png`. `.well-known/apple-app-site-association` (also generated)
lists `/invite/*` and `/auth/confirm*` for the app and the `webcredentials` entry. Caddy serves it as
`application/json`, rewrites `/invite/*` to the page and sends `Referrer-Policy: no-referrer` on both paths, so
the token never leaves the URL (ShipApp Caddyfile, `nix.shipapp.pl` block). After a deploy, Apple's CDN picks
the AASA up within a day: `https://app-site-association.cdn-apple.com/a/v1/nix.shipapp.pl`.
`npm run check:invite-hosting -- https://nix.shipapp.pl` checks the live headers and content type.

The old host, `nix.damianmotylinski.pl` (SEOHOST, `web/invite`), stays up until the invite links shared from
it have expired; the app still accepts its links (`FRIEND_INVITE_HOSTS`) and keeps its `applinks` entitlement.
Passkeys are still bound to the old host (`PASSKEY_RP_ID`, `webcredentials`); moving them is a separate
decision, because a new relying party id invalidates every passkey already registered.

## /auth/confirm/

Cel przycisku w mailach auth (potwierdzenie konta, reset hasła). Strona czyta `token_hash` i `type`
w przeglądarce, buduje przycisk „Otwórz w NiX” (`nix://auth/confirm?...`, obsługuje go
`src/lib/authDeepLink.ts`) i od razu usuwa zapytanie z paska adresu (`history.replaceState`). Nic nie
zapisuje i nic nie wysyła; Caddy nie ma `log` dla tej domeny. Universal Links dla nix.shipapp.pl
(otwieranie aplikacji bez tej strony) wymagają nowego builda z `applinks:nix.shipapp.pl`.
